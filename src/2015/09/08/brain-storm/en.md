Today I was writing JS—more precisely, JSX—but as I wrote I was not really in the zone. After closing all the tabs in Atom, I stared blankly at the editor, my thoughts wandering. Then I casually got off work and headed home, thinking of many things along the way.

It has been roughly eight years from the first line of JavaScript I wrote to now. That old JavaScript project was called "Guangzhou Daily Download Helper." Its file extension was not .js, but .jse. I believe many people do not even know such an extension exists. My high school classmates probably still remember it. Back in my second year of high school, I used it every morning to download the PDF of Guangzhou Daily, then stitch it into one large PDF for everyone to read during breaks. But apparently people read the sports pages more than the news... The reason it used the .jse extension was that .js was already claimed by the webpage editor by default. In fact, Windows has quite a few executable file types, such as vbs, vbe, js, jse, pif, com, and exe. As for vbs and vbe, I also had something more people might know, called "PPT to Images," a little tool with a .vbe extension. There was also another thing I made for fun called "VBSctipt Process Manager."

Looking at these things with modification dates from 2007 and 2008, I tried them again and found that after all these years, Microsoft's compatibility is still good enough to let them run on Windows 10! Let me briefly explain how they worked: "Guangzhou Daily Download Helper" used the current date to enumerate the download URLs of Guangzhou Daily PDFs through XMLHTTP, then used ADO.Stream to save the downloaded byte stream; "PPT to Images" used FSO to enumerate all PPT files in a directory and then called the Office DOM to save them as images. Back then all kinds of color-screen MP3/MP4 players were popular, and high school classrooms were starting to become informatized, so everyone used my tool to import PPTs onto their own devices to read. "VBSctipt Process Manager" called WMI APIs to get the current process list, then implemented process termination using WMI, taskkill, and NTSD. The motivation was simple: viruses at the time would kill Task Manager whenever it started, and the Task Manager back then also could not realistically show the command line and path of executables. I made this tool just to make computer repair more convenient.

Alright, after rambling so much, these are actually not what I most wanted to talk about today. What I really wanted to say is simply that they shared one common trait: they were all scripts, and they all used IE for the interface.

I say this because the Atom editor is made in basically the same way. Its interface is, in essence, a browser. The difference is that it uses WebKit rather than IE, and its engine is V8 rather than Windows Script. More precisely, the project behind it is called [Electron](http://electron.atom.io/). In the project's own words, it is used to "Build cross platform desktop apps with web technologies." Thinking about it gives me a faint sense of emotion. My use of IE that way back then was born of necessity. I did not know VB, much less MFC, so I saw a snippet using an IE control in some magazine somewhere, then used the little bit of table layout I had just learned to throw together an interface and build a few small tools.

What I continue to feel emotional about is Microsoft: a kind of technology that already existed many years ago was later implemented by another platform and then genuinely used in many products. You might ask, in what products? Microsoft's own VS Code, the productivity tool Slack that has been very popular lately, and so on—they are all derived from [Electron](http://electron.atom.io/). Eight years ago was absolutely an era in which IE completely dominated. But Microsoft never really thought about further strengthening IE's capabilities. Whether in terms of following W3C standards or improving performance, there was little change. It was only after Chrome suddenly appeared and its version numbers started jumping like a rocket that the entire web world underwent earth-shaking changes over the past three or four years. The [Electron](http://electron.atom.io/) project, even more so, has given Web Applications a new posture for seizing territory from Desktop Applications. Yes—after using Atom and VS Code, I also ask myself: aside from being small, does Notepad++ really have any advantage left?

From another angle, though, IE back then really had little motivation to improve performance. It was already the fastest and best. And at the time, Mac and Linux users together made up less than 1%, so there was no need for cross-platform support. But today, the world has truly changed. It is not only that we have faster browsers and faster scripting engines, nor only that there are more operating systems for people to choose from. Even the entire PC market has gradually given a large share to mobile. Microsoft has also released the new browser Edge, and its performance really is quite good. But one thing that disappointed me a little was hearing in an internal talk that it had not considered supporting older versions of Windows, nor had it (for the time being) considered landing on other platforms.

You could say Microsoft is good in that it has built a mature ecosystem of its own and does very stable work. A script from many years ago can still run today without much trouble. But now other ecosystems are rising too, and some of Microsoft's moves to bring things from its own ecosystem into others are really not direct and decisive enough (only in some cases, that is; in recent years it has actually become more and more open). My feelings toward Microsoft are genuinely complicated. As a fresh graduate who joined Microsoft after college, I really disliked the Windows terminal. It did not even support adjusting the window size properly, and all sorts of automation tools were far inferior to those on *uinx. Yet at the same time, all the good things about C# and .NET really appealed to me. To put it plainly, looking from the rise of the mobile internet to the present, my conclusion is that Microsoft failed to win over developers, and if developers would not help Microsoft win over users, then...

I first saw the [Electron](http://electron.atom.io/) project a few days ago and looked through quite a few interesting downstream products, but I had been too busy and had no time to think much about it. Actually, when I got to this point, it gave me a bit of a jolt. I had become so busy that I did not even have time to think about things worth thinking about. If a person does not think, how are they any different from a salted fish?

Alright, enough nonsense. If you are interested, here are [the scripts from back then](https://winguse.com/blog/2015/09/08/brain-storm/the_old_scripts/). I wrote them when I was young. I do not think I recovered the well-indented, commented versions, and they may not run perfectly anymore.
